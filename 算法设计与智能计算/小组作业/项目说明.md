# TSP Memetic Algorithm 项目说明


---

## 1. 项目概述

本项目围绕旅行商问题（Travelling Salesman Problem, TSP）复现和扩展论文：

> P. Merz, B. Freisleben, *Memetic Algorithms for the Traveling Salesman Problem*, Complex Systems, 2001.

我们关注的问题是：

> 在 TSP 中，什么样的遗传信息值得继承？交叉算子和局部搜索怎样配合，才能稳定提高解的质量？

## 3. 背景和术语

### 3.1 一些遗传算法术语在本项目中的实际含义

| 遗传算法术语 | 本项目含义 |
|---|---|
| individual / 个体 | 一条候选 TSP tour |
| chromosome / 染色体 | tour 的城市排列编码 |
| population / 种群 | 多条候选 tour 的集合 |
| fitness / 适应度 | 个体好坏；TSP 中路线越短越好 |
| selection / 选择 | 让较好个体更容易成为父代 |
| crossover / 交叉 | 两个父代生成子代 |
| mutation / 变异 | 对子代做随机小扰动 |
| generation / 代 | 一轮选择、交叉、变异、更新 |
| elitism / 精英保留 | 每代直接保留若干最好个体 |

因为 TSP 是最小化问题，而 GA 通常把 fitness 设为越大越好，代码里常用：

```text
fitness = -tour_length
```

### 3.2 Memetic Algorithm

Memetic Algorithm（MA）可以理解为遗传算法全局搜索 + 局部搜索精修。普通 GA 产生子代后通常直接进入下一代；而 MA 会先对子代做局部搜索，让它变成更短的 tour，再进入种群。
主流程为：

```text
初始化种群-> 选择父代-> 交叉和变异生成子代-> 局部搜索修复子代-> 精英保留和种群更新-> 重复多代
```

### 3.5 指标

实验中最重要的结果指标是 `Final Gap`。

```text
Final Gap = (算法最终路径长度 - 已知最优路径长度) / 已知最优路径长度 * 100%
```

gap 越小，说明越接近已知最优解。

其他指标：

| 指标 | 含义 |
|---|---|
| best-so-far gap | 到当前代为止找到的最好 gap |
| final gap | 算法结束时的 gap |
| std | 多次随机运行的标准差，反映波动 |
| seed | 随机种子，用于复现实验随机过程 |
| runtime | 平均运行时间 |

需要强调的是，TSPLIB 给出的已知最优值是评价基准；本项目的启发式算法本身不证明全局最优。

## 4. TSP 中边的重要性

城市排列只是编码方式，真正决定 tour 长度的是相邻城市之间的边。例如：

```text
tour = [0, 3, 1, 2]
```

对应边集合：

```text
(0,3), (3,1), (1,2), (2,0)
```

在对称 TSP 中，`(3,1)` 和 `(1,3)` 是同一条无向边。所以，TSP 交叉应优先保证边结构，再考虑如何补成合法回路。项目中用 `tour_edges` 把排列转换为边集合，并用边结构指标分析不同交叉算子：

| 指标 | 含义 |
|---|---|
| common edge | 两个父代都包含的边 |
| foreign edge | 子代中有、但两个父代都没有的边 |
| common edge preservation rate | 父母共同边被子代保留的比例 |
| parent edge inheritance rate | 子代边中来自父代的比例 |

最终使用的代表性结果：

| 算子 | 共同边保留率 | 平均 foreign edges |
|---|---:|---:|
| OX | 0.976 | 5.20 |
| PMX | 0.896 | 16.50 |
| DPX | 1.000 | 44.88 |
| GX | 1.000 | 23.08 |

- OX/PMX 主要保证排列合法，对共同边没有硬约束。
- DPX/GX 明确保留共同边，所以共同边保留率为 1.000。
- DPX 引入的 foreign edges 更多，因此探索性更强，但也更依赖后续局部搜索修复。
- GX 也引入新边，但更偏向短边和父代边，通常更稳定。

## 5. 交叉算子

### 5.1 OX 、PMX

OX（Order Crossover）和 PMX（Partially Mapped Crossover）是排列交叉算子。它们重点解决的问题是：子代必须仍然是合法排列，不能重复城市，也不能漏城市
这对 TSP 是必要条件，但不是充分条件，因为 TSP 的好坏由边决定，保留城市顺序片段或位置映射，不一定保留父代中的好边。PPT 第 4、5 页以 PMX 为例说明了PMX child 是合法 tour，但父代共同边被明显打断。

### 5.2 DPX：保共同边，再重连片段

DPX（Distance Preserving Crossover）的核心思想是：

1. 找出父代共同边；
2. 尽量保留这些共同边；
3. 共同边会形成若干片段；
4. 用新边把片段重新连接成完整 tour。

在项目实现中，DPX 会避免提前形成小环，并用距离信息贪心重连片段。DPX 强制保留共同边，同时引入较多新连接，探索能力强，但 foreign edges 多，子代可能比较粗糙。因此 DPX 单独或配弱局部搜索时不一定突出，但配合 L-K 后更容易发挥探索价值。

### 5.3 GX：保共同边、加短新边、继承父代边、贪心补全

GX（Generic Greedy Recombination）是项目中重点展示的边结构交叉。它按边集合构造子代，默认分四步：

1. **复制共同边**：父母都拥有的边优先保留。
2. **加入少量短新边**：提供探索，但优先选择短边。
3. **继续继承父代边**：从父代边中选择可行、较短的边。
4. **贪心补全成完整 tour**：保证每个城市度数为 2，并避免提前形成小环。

GX 相比 OX/PMX，更尊重 TSP 的边结构；foreign edges 少一些，起点更稳定。代价是构造过程更复杂，运行时间通常更高。

## 6. 局部搜索

### 6.1 为什么需要局部搜索

交叉产生的子代只是一个候选 tour。即使它继承了不错的边，也可能存在明显可改进的长边连接。
局部搜索的过程是：

```text
从当前 tour 出发-> 尝试小范围改动-> 只接受变短的改动-> 直到找不到明显改进
```

因此 MA 中的局部搜索起修复作用，把交叉产生的结构修到更好的局部最优。

### 6.2 2-opt：固定交换两条边

2-opt 删除 tour 中两条边，并把中间片段反转后重连。比如如果原来有：

```text
... A -> B ... C -> D ...
```

2-opt 尝试改成：

```text
... A -> C ... B -> D ...
```

如果新路线更短，就接受。2-opt 的优点是简单、快，能消除明显交叉；但邻域较浅，容易卡在较差的局部最优。

### 6.3 Lin-Kernighan：自适应 k-opt

Lin-Kernighan（L-K）不是固定只换两条边，而是动态决定交换链能走多深。可以概括为：

```text
先删一条边-> 加一条新边-> 再删一条边-> 再加一条新边-> 如果累计收益仍有希望，就继续-> 找到更短闭环后接受
```

项目中的 L-K 是有界实现。它用参数控制搜索规模：

| 参数 | 含义 |
|---|---|
| warm start | L-K 前先做多少 2-opt 预修复 |
| max improvements | 最多接受多少次 L-K 改进 |
| max depth | 一条交换链最多搜索多深 |
| candidate k | 每个城市考虑多少个近邻候选 |
| backtracking width | 每层保留多少个候选分支 |

PPT 第 13 页的 L-K 强度实验就是改变这些预算参数。结果显示，L-K 太弱时修复不足；中等强度已经明显改善；继续增强不一定单调变好，因为质量、时间、种群多样性之间存在权衡。

## 7. Memetic 主循环

核心代码在：

```text
tsp_memetic/src/memetic.py
```

简化流程可以概括为：

```text
1. 初始化种群
2. 对初始个体做局部搜索
3. 每一代：
   3.1 保留精英个体
   3.2 锦标赛选择父代
   3.3 用 OX/PMX/DPX/GX 等算子生成子代
   3.4 对子代做变异
   3.5 对子代做 2-opt 或 L-K 局部搜索
   3.6 合并并截断为新的种群
   3.7 记录 best gap、边继承率、多样性等统计
```

PPT 第 8 页展示了主循环，第 9 页展示了 GX 和 L-K 的核心代码。项目主实验采用的是 Lamarckian 风格，局部搜索后的改进结果直接写回染色体，后续交叉也使用改进后的 tour。

## 8. 实验过程

### 8.1 实验实例

由于本地运算能力限制，项目使用 TSPLIB 实例，展示结果包括：

| 实例 | 城市数 | 用途 |
|---|---:|---|
| `eil51` | 51 | 多地图稳定性验证 |
| `eil101` | 101 | 多地图稳定性验证 |
| `ch130` | 130 | 参数探索、多 seed、L-K 强度、种群规模 |
| `d493` | 493 | 主实验大实例，对比最终性能 |

这些示例均有已知最优解，经过多方面反复验证。比如`d493` 的已知最优值为 `35002`。

### 8.2 主实验：d493

`d493` 主实验设置：

| 参数 | 值 |
|---|---:|
| runs | 10 |
| generations | 8 |
| pop_size | 6 |
| crossover probability | 0.9 |
| mutation probability | 0.2 |
| L-K warm start budget | 100000 |
| L-K max improvements | 12 |
| L-K max depth | 3 |
| L-K candidate k | 20 |
| L-K backtracking width | 1 |

最终结果：

| 方法 | Final Gap 均值 | 标准差 | 平均时间 |
|---|---:|---:|---:|
| OX + no LS | 23.014% | 2.019 | 0.059s |
| OX + 2-opt | 5.094% | 0.611 | 8.519s |
| PMX + 2-opt | 5.116% | 0.529 | 9.333s |
| DPX + 2-opt | 5.251% | 0.619 | 10.190s |
| GX + 2-opt | 4.233% | 0.453 | 22.511s |
| OX + L-K | 4.088% | 0.641 | 14.791s |
| PMX + L-K | 3.966% | 0.469 | 15.502s |
| DPX + L-K | 3.709% | 0.709 | 17.720s |
| GX + L-K | 3.317% | 0.820 | 26.439s |

主要结论：

1. 无局部搜索的 GA 很快，但 final gap 约 23%，质量明显不足。
2. 2-opt 将 gap 降到约 4-5%，说明局部搜索是主要提升来源。
3. L-K 进一步降低 gap，说明更强邻域搜索能继续修复 tour。
4. 在 L-K 组合中，GX + L-K 平均 gap 最低。

### 8.3 多地图验证：GX + L-K 的稳定性

加入了 `eil51/eil101/ch130/d493` 多地图对比。

| 实例 | OX + L-K | PMX + L-K | DPX + L-K | GX + L-K |
|---|---:|---:|---:|---:|
| `eil51` | 0.440% | 0.440% | **0.147%** | 0.323% |
| `eil101` | 1.808% | 1.868% | 1.987% | **0.795%** |
| `ch130` | 1.289% | 1.833% | **0.708%** | 1.197% |
| `d493` | 4.088% | 3.966% | 3.709% | **3.317%** |

GX + L-K 在 `eil101` 和 `d493` 上最优；在 `eil51` 和 `ch130` 上次优。整体稳定，尤其在较大实例 d493 上表现最好。
DPX + L-K 探索性更强，但更依赖 seed、父代质量和 L-K 修复。

### 8.4 L-K 强度实验

比较弱、中、强三档 L-K 参数。

| 强度 | warm start | max improvements | max depth | candidate k | backtracking width |
|---|---:|---:|---:|---:|---:|
| weak | 20 | 1 | 2 | 8 | 1 |
| medium | 60 | 3 | 3 | 12 | 2 |
| strong | unbounded | 5 | 3 | 15 | 3 |

`ch130` 上的结果：

| L-K 强度 | OX + L-K | DPX + L-K | GX + L-K |
|---|---:|---:|---:|
| weak | 4.096% | 4.673% | 3.392% |
| medium | 1.502% | 1.751% | 1.493% |
| strong | 1.968% | 1.604% | 1.563% |

weak 修复不足，gap 明显偏高；medium 已经显著改善。strong 并不保证继续单调变好，例如 OX + L-K 反而变差。所以更强 L-K不是无条件更优。强度需要和交叉算子、代数、种群规模、时间预算匹配。

### 8.5 种群规模与多 seed

解释两个问题：种群规模变大是否一定更好？DPX 为什么波动更大？

#### 种群规模

`ch130` 上，固定代数后比较 `pop_size=6` 和 `pop_size=12`：

| 方法 | pop=6 Final Gap | pop=12 Final Gap |
|---|---:|---:|
| GX + 2-opt | 2.050% | 2.357% |
| DPX + L-K | 2.021% | 0.720% |
| GX + L-K | 1.162% | 0.491% |

种群变大提供更多候选子代，但因为 2-opt 修复较浅，更多多样性未必能转化为更好的局部最优；配合 L-K 时，更多候选结构更容易被修成高质量子代，因此 DPX/GX + L-K 更稳定受益。

#### 多 seed 稳定性

`ch130` 多 seed 结果：

| 方法 | Final Gap 均值 | 标准差 | 最好 seed | 最差 seed |
|---|---:|---:|---:|---:|
| PMX + L-K | 1.056% | 0.151 | 0.802% | 1.260% |
| DPX + L-K | 1.227% | 0.628 | 0.426% | 2.455% |
| GX + L-K | 0.931% | 0.273 | 0.491% | 1.326% |
| GX + 2-opt | 1.512% | 0.562 | 0.311% | 2.062% |

DPX 波动更大，是因为会引入更多 foreign edges。这可能带来跳出父代结构的好机会，也可能引入坏连接。如果 seed 较好，父代共同边质量高，新边能被 L-K 修成好结构；反之新边会增加 L-K 修复负担，有限预算下修不干净。

因此 DPX 是探索性强、收益和风险都更高的算子；GX 更偏向稳定继承，因此波动通常小一些。

## 9. 结论

PPT 第 15 页的结论为以下四点。

### 9.1 TSP 的主要遗传信息是边结构

路线长度由相邻城市边决定，不由城市在数组里的绝对位置决定。因此 TSP 交叉算子不能只满足“排列合法”，还要考虑是否保留优秀父代的边。

### 9.2 DPX 需要足够强的局部搜索

DPX 的价值在于探索：它保留共同边，同时引入较多 foreign edges。新边可能带来突破，也可能破坏结构。因此 DPX + 2-opt 不一定突出，而 DPX + L-K 才能较好发挥作用。

### 9.3 GX 更偏向稳定继承

GX 也保留共同边，但新边加入更受距离和可行性约束，整体更保守、更稳定。比如在 `d493` 和 `eil101` 上，GX + L-K 获得最低平均 gap。

### 9.4 MA 的优势来自协同

交叉产生结构差异，局部搜索负责修复。二者互相匹配时，Memetic Algorithm 才能稳定优于普通 GA。
